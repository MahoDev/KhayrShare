# Implementation Plan: Smart Suggestion Fairness

**Branch**: `005-smart-suggestion-fairness` | **Date**: 2026-07-08 | **Spec**: [spec.md](./spec.md)  
**Input**: Feature specification from `specs/005-smart-suggestion-fairness/spec.md`

## Summary

The khayr-suggestor and khayr-media-gen background services produce repetitive suggestions because both use pure random selection with no memory of what was suggested within the same day. This feature adds:

1. **Within-day group dampening** for khayr-suggestor — groups already suggested today have a drastically reduced selection weight (but are not eliminated), giving under-suggested groups a fair chance.
2. **Daily reciter round-robin** for khayr-media-gen — each reciter appears once before any reciter repeats; auto-resets when all reciters are exhausted or a new day begins.
3. **On-demand regeneration** via a `regenerate: true` flag in the video suggestion `.txt` file — the user sets this flag to trigger a fresh video for the same reciter instantly.

**Language/Version**: Node.js (existing, CommonJS)  
**Primary Dependencies**: `luxon` (existing, date handling), `fs` (built-in), `node-cron` (existing)  
**Storage**: Filesystem — two new JSON tracker files in existing output directories  
**Testing**: Manual CLI testing + existing test scripts  
**Target Platform**: Windows Desktop (local)  
**Project Type**: Automation Service / Background Scheduler  
**Performance Goals**: No measurable overhead; JSON read/write on each scheduler tick  
**Constraints**: Must not break existing `finishedPosting` or `postedGroups` flows; no new npm dependencies  
**Scale/Scope**: Local, single-user, single process

## Constitution Check

*GATE: Passed*

- **Modular Architecture**: Changes are isolated to `manual-assistant.js` (suggestor) and `generator.js` / `scheduler.js` (media-gen). No new cross-service dependencies introduced.
- **Configuration Externalization**: The new `sameDayDampeningFactor` setting is added to the existing `config.json` (suggestor) with a documented default. No hardcoded credentials or environment paths.
- **Test-First Development**: Manual test scenarios are defined in `quickstart.md`. The round-robin pool can be exercised by deleting `daily_reciter_pool.json` and calling `generate()` in sequence.
- **Observability & Logging**: All new code paths emit `console.log` with `[VideoGen]` and `[manual-assist]` prefixes consistent with existing logging conventions.
- **Graceful Degradation**: Missing or corrupt tracker files are handled by treating them as empty/reset state and continuing normally. Malformed `regenerate` files log a warning and skip.
